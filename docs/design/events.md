# Events 域 — 设计文档

> 状态：**已实现**（`main`）；NuGet `Observables.Events.R3` / `Observables.Events.Reactive`（随库 **`0.2.2`** 发布）。
> 命名、打包、诊断分段以 [`AGENTS.md`](../../AGENTS.md) 为权威。

## 1. 目标与定位

将 .NET 事件（经典 `event`、`EventHandler`、WPF/Avalonia 路由事件）桥接为反应式流。Events 是十域中**唯一的纯生成域**：`Observables.Events` 仅含 MSBuild props，桥接类型由生成器 `internal` 产出。

## 2. API 面

### NuGet 包

| 包 ID | 后端 | 运行时 |
|-------|------|--------|
| `Observables.Events.R3` | R3 | 无（纯生成；仅 MSBuild props） |
| `Observables.Events.Reactive` | System.Reactive | 无 |

### 入口扩展方法（按使用即生成）

| 方法 | 返回形状 | 场景 |
|------|----------|------|
| `.Events()` | `Observable<T>` / `IObservable<T>` | 事件载荷，去掉 `sender` |
| `.EventHandlers()` | `Observable<(object? sender, TEventArgs e)>` | 保留 `sender` 与 `EventArgs` |
| `.RoutedEvents()` | `Observable<T>` | WPF/Avalonia 路由事件（须开启开关） |
| `.RoutedEventHandlers()` | `Observable<(object? sender, TEventArgs e)>` | 路由事件保留 sender |
| `.AttachedRoutedEvent<T>()` | `Observable<TEventArgs>` | Avalonia 附加静态路由事件字段（仅编译中存在 Avalonia 路由类型时发射） |
| `.AttachedRoutedEventHandler<T>()` | `Observable<(object?, TEventArgs)>` | Avalonia 附加路由事件 + sender |

生成器产出：`I{Type}Events` / `{Type}EventsImpl`（路由变体为 `I{Type}RoutedEvents` / `{Type}RoutedEventsImpl` 等）、`internal static partial class ObservableEventsBootstrapExtensions` 内的扩展方法；桥接类型 `EventObservable`（仅 R3）、`NullEvents` 为 `internal`。

### MSBuild 配置

| 属性 | 默认 | 说明 |
|------|------|------|
| `ObservableRoutedEvents` | `false` | `true` 时启用路由事件相关入口 |
| `UseWPF` | 自动检测 | 影响 WPF 路由事件识别 |

实际打包的是 `Observables.Events.Package/build/Observables.Events.{R3,Reactive}.props`（buildTransitive）。

### 检测规则

- **经典事件**：类型上任何 `event` 成员（含继承、含接口树）。
- **路由事件**：实例事件对应**可访问的**静态字段 `{Name}Event`，类型为 WPF `System.Windows.RoutedEvent` 或 Avalonia `Avalonia.Interactivity.RoutedEvent`/`RoutedEvent<T>`（非泛型 Avalonia `RoutedEvent` 走非泛型 `AddHandler` 重载）。
- **附加路由事件**：Avalonia only。调用方显式传入静态 `RoutedEvent` 字段引用；WPF 工程即使开启 `UseWPF` 也不发射 `AttachedRouted*`（WPF 实例路由走 `.RoutedEvents()` / `.RoutedEventHandlers()`）。
- **可见性过滤**：只发射消费程序集可访问的形状——事件成员可经 `Compilation.IsSymbolAccessibleWithin` 从生成代码触达（`_sender.E` 直接访问或 `(I) sender).E` 显式接口访问），且委托/事件参数类型可访问。跨程序集 `internal` 接口/基类上声明的事件、以及引用不可访问参数类型的事件会被跳过（GitPulse MAUI CS0122 的根因修复，见 §10）。

## 3. 诊断 ID

| ID | 级别 | 触发条件 | helpLinkUri |
|----|------|----------|-------------|
| OBS2001 | Warning | `.Events()` — 不支持的委托签名 | `…/diagnostics.html#obs2001` |
| OBS2002 | Warning | `.EventHandlers()` — 非 EventHandler / `(object, T)` 形态 | `#obs2002` |
| OBS2003 | Warning | `.RoutedEvents()` — 不支持的路由委托 | `#obs2003` |
| OBS2004 | Warning | `.RoutedEventHandlers()` — 不支持的路由处理器 | `#obs2004` |
| OBS2005 | Error | Events 源生成器内部错误 | `#obs2005` |
| OBS2006 | Warning | 同名事件在接口合并中委托类型不兼容（该事件被跳过） | `#obs2006` |

类别：`Observables.Events`。OBS2001–2004、OBS2006 为 Warning（跳过该事件，不阻塞编译）；OBS2005 为 fail-safe 内部错误。

## 4. 不变量

1. Events 域**无公共运行时类型**；消费者仅引用 NuGet 包即可获得生成器与 props。
2. R3 与 Reactive 包**不得**同时作为同一功能域的依赖（共享分析器 OBS0001 适用全库；该分析器对 Events/RestAPI 的检测目前存在覆盖缺口，见工程债台账 S-1）。
3. 生成代码均带 `// <auto-generated/>` 头与 `#pragma warning disable`（`GeneratedSourceHeader`）。
4. 路由事件生成默认关闭，避免未使用 WPF/Avalonia 的项目引入路由 API。
5. 入口方法在任何类型上都能绑定（bootstrap stub 返回 `NullEvents`），但**只有生成了对应事件的属性才能访问**——`x.Events().SomeEvent` 在无事件时仍是编译错误（CS1061）。空回退保的是「调用入口」而非「成员访问」。
6. 某类型上全部可生成事件均被 OBS2001–2004/可见性过滤跳过时，不产出该类型的 impl（接口若仍含可发射成员则保留）；诊断仍报告。

## 5. 生成映射

### 5.1 经典事件 → `Observable<T>`

对每个被 `.Events()` 触达的类型，生成器产出（R3 路，Verify 快照节选）：

```csharp
namespace Observables.Events.R3;

internal static partial class ObservableEventsBootstrapExtensions
{
    public static IButtonEvents Events(this global::Avalonia.Controls.Button source)
        => new ButtonEventsImpl(source);
}

internal interface IButtonEvents
{
    global::R3.Observable<global::Avalonia.Interactivity.RoutedEventArgs> Click { get; }
}

internal sealed class ButtonEventsImpl : IButtonEvents
{
    private readonly global::Avalonia.Controls.Button _sender;
    internal ButtonEventsImpl(global::Avalonia.Controls.Button sender) => _sender = sender;

    public global::R3.Observable<global::Avalonia.Interactivity.RoutedEventArgs> Click =>
        global::Observables.Events.R3.EventObservable.Event<global::System.EventHandler<global::Avalonia.Interactivity.RoutedEventArgs>, global::Avalonia.Interactivity.RoutedEventArgs>(
            h => (sender, e) => h(e),
            h => _sender.Click += h,
            h => _sender.Click -= h,
            default);
}
```

`EventObservable.Event<TDelegate, T>` 内部调用 `R3.Observable.FromEvent(conversion, add, remove, ct)`；Reactive 包对应桥接为 `System.Reactive.Linq.Observable.FromEvent(...)`，接口/实现同构但返回 `IObservable<T>`。

### 5.2 EventHandler 系 → `Observable<(object?, T)>`

`.EventHandlers()` 对 `System.EventHandler` / `EventHandler<T>` 走专用桥：

```csharp
public global::R3.Observable<(object? sender, global::System.ComponentModel.PropertyChangedEventArgs e)> PropertyChanged =>
    global::Observables.Events.R3.EventObservable.EventHandler<global::System.ComponentModel.PropertyChangedEventArgs>(
        h => _sender.PropertyChanged += h,
        h => _sender.PropertyChanged -= h,
        default);
```

非泛型 `EventHandler` 退化为 `Observable<(object?, EventArgs)>`。

### 5.3 路由事件（Avalonia 示例）

`ObservableRoutedEvents=true` 且检测到 Avalonia 路由字段时：

```csharp
public static IButtonRoutedEvents RoutedEvents(this global::Avalonia.Controls.Button source)
    => new ButtonRoutedEventsImpl(source, global::Avalonia.Interactivity.RoutingStrategies.Direct | global::Avalonia.Interactivity.RoutingStrategies.Bubble, false);
public static IButtonRoutedEvents RoutedEvents(this global::Avalonia.Controls.Button source, global::Avalonia.Interactivity.RoutingStrategies routes, bool handledEventsToo = false)
    => new ButtonRoutedEventsImpl(source, routes, handledEventsToo);

internal sealed class ButtonRoutedEventsImpl : IButtonRoutedEvents
{
    private readonly global::Avalonia.Controls.Button _sender;
    private readonly global::Avalonia.Interactivity.RoutingStrategies _routes;
    private readonly bool _handledEventsToo;
    internal ButtonRoutedEventsImpl(global::Avalonia.Controls.Button sender, global::Avalonia.Interactivity.RoutingStrategies routes, bool handledEventsToo) { ... }

    public global::R3.Observable<global::Avalonia.Interactivity.RoutedEventArgs> Click =>
        EventObservable.Event<EventHandler<RoutedEventArgs>, RoutedEventArgs>(
            h => (sender, e) => h(e),
            h => _sender.AddHandler<global::Avalonia.Interactivity.RoutedEventArgs>(global::Avalonia.Controls.Button.ClickEvent, h, _routes, _handledEventsToo),
            h => _sender.RemoveHandler<global::Avalonia.Interactivity.RoutedEventArgs>(global::Avalonia.Controls.Button.ClickEvent, h),
            default);
}
```

`_routes` 强类型为 `Avalonia.Interactivity.RoutingStrategies`；字段访问为 `ContainingType.XxxEvent` 完全限定静态引用；非泛型 `RoutedEvent` 字段走非泛型 `AddHandler(RoutedEvent, Delegate, …)` 重载。

WPF 无 `RoutingStrategies` 参数；`UseWPF=true` 时生成 `AddHandler(routedEvent, handler, handledEventsToo)` / `RemoveHandler(routedEvent, handler)`（非泛型重载，handler 为 `Delegate`），不回退 CLR `+=`。

### 5.4 附加路由事件

Discovery 仅在编译中解析到 Avalonia `RoutedEvent` / `RoutedEvent<T>` 时收集 `AttachedRoutedEvent` / `AttachedRoutedEventHandler`。WPF 的 `UseWPF` 只驱动实例 `.RoutedEvents()`，不驱动附加入口。

```csharp
public static global::R3.Observable<TEventArgs> AttachedRoutedEvent<TEventArgs>(
    this global::Avalonia.Controls.Control source,
    global::Avalonia.Interactivity.RoutedEvent<TEventArgs> routedEvent,
    global::Avalonia.Interactivity.RoutingStrategies routes = global::Avalonia.Interactivity.RoutingStrategies.Direct | global::Avalonia.Interactivity.RoutingStrategies.Bubble,
    bool handledEventsToo = false)
    where TEventArgs : global::Avalonia.Interactivity.RoutedEventArgs
    => EventObservable.Event<EventHandler<TEventArgs>, TEventArgs>(
        h => (sender, e) => h(e),
        h => source.AddHandler<TEventArgs>(routedEvent, h, routes, handledEventsToo),
        h => source.RemoveHandler<TEventArgs>(routedEvent, h),
        default);
```

### 5.5 空回退

`NullEvents`（`internal struct`）作为 bootstrap stub 的返回类型：post-init 与路由 stub 分别发射 `Events(this object?)` / `EventHandlers(this object?)` / `RoutedEvents(this object?, …)` 等兜底扩展，保证入口调用在未生成具体类型时仍可绑定（返回 `default(NullEvents)`）。**它不提供事件成员**——`.Events().SomeEvent` 在无对应生成时仍 CS1061。

### 5.6 泛型约束目标

当 `.Events()` 的接收者是泛型参数（如 `where T : INotifyPropertyChanged`）时，生成器走 `GenericConstraintTarget` 路径：按约束类型集生成 `I{Combined}Events` / `{Combined}EventsImpl<TSource>` 与 `ObservableEventsBootstrapExtensions_{Key}`（`internal static partial`，Events 与 EventHandlers 两个入口可共存于同名 partial 类）。事件访问经约束成员的显式接口访问或 `_sender.E` 直访，同样受可见性过滤约束。

## 6. 生成器管道

`ObservableEventsGenerator : IIncrementalGenerator`（R3 与 Reactive 各一份，结构一致，`#if EVENTS_R3` 切换）：

1. **PostInitializationOutput**：产出 `ObservableEventsBootstrapExtensions.g.cs`（`Events`/`EventHandlers` 空回退 stub）、`NullEvents.g.cs`、（R3）`EventObservable.g.cs` 桥。
2. **SyntaxProvider**：`IsObservableEventsInstanceEntryInvocation` 过滤 `.Events()` / `.EventHandlers()` / `.RoutedEvents()` / `.RoutedEventHandlers()` / `.AttachedRoutedEvent<T>()` / `.AttachedRoutedEventHandler<T>()` 调用节点。
3. **AnalyzerConfigOptionsProvider**：读取 `build_property.ObservableRoutedEvents` 与 `build_property.UseWPF`。
4. **Combine + Collect**：候选节点 × `CompilationProvider` × 配置。
5. **Parse**（`ParseEvents`，值相等 emission model，无符号逃逸）：
   - `CollectObservableEventTargets` 按入口类型分类收集 `ObservableEventTargetSets`（经典目标走语义绑定到 post-init stub；路由/附加目标走语法+接收者类型解析，因为路由 stub 由下一步 `RegisterSourceOutput` 产出、本轮编译不可见）。
   - `CollectEmissionSources` 为 `Events` / `EventHandlers` / `RoutedEvents` / `RoutedEventHandlers` 各产出接口 + 实现 + 扩展方法；`AttachedRouted*` 按接收类型单独产出 `*.AttachedRoutedEvent{,Handler}.g.cs`。
6. **RegisterSourceOutput**（`EmitParsedModel`）：回放捕获诊断（OBS2001–2006），`AddSource` 各 emission 文件；路由 bootstrap stub（`*.Routed.g.cs`）仅在 `ObservableRoutedEvents=true` 时产出。

## 8. 关键设计决策

| 决策 | 理由 |
|------|------|
| **纯生成，无运行时** | Events 域无运行时状态；`Observables.Events` 仅承载 MSBuild props |
| **接口 + 实现 + 扩展方法三件套** | 类型安全的事件访问；接口便于 mock 与测试 |
| **`.Events()` vs `.EventHandlers()` 双入口** | 前者按委托签名推断载荷元组，后者归一为 `(sender, e)` 形态 |
| **路由事件默认关闭** | 避免 WPF/Avalonia 依赖污染；消费者显式开启 |
| **WPF / Avalonia 自动检测** | 通过静态字段 `{EventName}Event` 的类型元数据判定，无需显式配置 |
| **附加路由事件独立入口** | Avalonia：在父元素上订阅外国类型的静态 `RoutedEvent` 字段。WPF 不发射该入口 |
| **`NullEvents` 空回退** | 入口调用始终可绑定（返回 `default(NullEvents)`），避免「找不到扩展方法」级破坏；不提供成员兜底 |
| **可见性过滤（`IsSymbolAccessibleWithin`）** | 跨程序集继承树上声明的事件只有生成代码能合法触达时才发射，杜绝 CS0122（替代 GitPulse ADR-015 的手工 adapter 绕行） |
| **接口合并冲突 → OBS2006 + 跳过该事件** | 同名不同委托的事件不做任意选择：从合并面剔除并告警 |
| **静态事件路径已删除** | `ObservableEventsStatics`/`OBS_*` 半成品（原 `StaticObservableEventsGenerationEnabled=false` 遮蔽）整体移除；静态事件如需支持重新设计 |
| **诊断** | OBS2001–2004、OBS2006 为 Warning；OBS2005 为内部错误 fail-safe |

## 9. 兼容基线

- 生成器 TFM：`netstandard2.0`（Roslyn 组件）
- 消费者：任意支持源生成器的 .NET 项目；路由事件需引用 WPF 或 Avalonia
- 发现边界：层级展开跟随 `BaseType`/`Interfaces` **跨程序集**递归（真实边界不是本程序集——这也是 MAUI `internal` 接口事件曾穿透进来产生 CS0122 的原因）；过滤以**生成代码可访问性**为准，不是以程序集边界为准。
