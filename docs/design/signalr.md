# SignalR Feature — 开发设计文档

> 状态：**已实现并发布** — NuGet `0.1.0-preview3`（`Observables.SignalR.R3` / `Observables.SignalR.Reactive`）。本文保留设计决策与项目清单；实现细节以代码与 [`docs/signalr.md`](../signalr.md) 为准。对应 Issue [#44](https://github.com/Skymly/Observables/issues/44)。
> 命名、打包、诊断分段等约定以仓库根 [`AGENTS.md`](../../AGENTS.md) 为权威，本文在其框架内细化 SignalR 域。

## 1. 目标与定位

将 **ASP.NET Core SignalR 客户端**（`Microsoft.AspNetCore.SignalR.Client.HubConnection`）的两类通信边界，通过 Roslyn 源生成器桥接为反应式流：

| 边界 | 方向 | SignalR 原生 API | 对应已实现范本 |
|------|------|------------------|----------------|
| **调用 Invoke** | 客户端 → 服务端，单结果 | `InvokeAsync<T>(method, args…)` | RestAPI（请求/响应，冷流单元素） |
| **发送 Send** | 客户端 → 服务端，无返回 | `SendAsync(method, args…)` | RestAPI（返回 `Observable<Unit>`） |
| **流式 Stream** | 客户端 → 服务端，多结果 | `StreamAsync<T>(method, args…)` → `IAsyncEnumerable<T>` | 无（新增：异步序列 → 多元素流） |
| **回调 On** | 服务端 → 客户端，多次 | `On<T>(method, handler)` → `IDisposable` | Events（回调注册 → 热流） |

最终发布 **两个 NuGet 包**（与 Events/RestAPI 对齐）：

- `Observables.SignalR.R3`（R3 后端）
- `Observables.SignalR.Reactive`（System.Reactive 后端）

## 2. API 规划

### 2.1 接口优先模型（主形态，对齐 RestAPI + MagicOnion「接口即协议」）

消费者声明一个 **Hub 代理接口**，用特性标注每个成员的边界类型；调用与回调可写在同一接口内：

```csharp
using Observables.SignalR;
using R3;

[Hub]
public interface IChatHub
{
    // 客户端 → 服务端：单结果调用（订阅时触发 InvokeAsync，冷流，发一个元素后完成）
    [HubInvoke]
    Observable<int> GetUserCount();

    // 客户端 → 服务端：无返回发送（订阅时触发 SendAsync，发 Unit 后完成）
    [HubSend("Send")]
    Observable<Unit> Send(string user, string message);

    // 客户端 → 服务端：服务端流式下行（桥接 IAsyncEnumerable<T> → 多元素流）
    [HubStream("Counter")]
    Observable<int> Counter(int count, int delayMs);

    // 服务端 → 客户端：回调流（订阅时 connection.On(...)，热/多播；释放订阅时注销）
    [HubOn("ReceiveMessage")]
    Observable<ChatMessage> ReceiveMessage { get; }
}
```

获取实现：

```csharp
HubConnection connection = new HubConnectionBuilder()
    .WithUrl("https://example.com/chathub")
    .Build();
await connection.StartAsync();

IChatHub hub = HubService.For<IChatHub>(connection);

using var d = hub.ReceiveMessage.Subscribe(msg => Console.WriteLine(msg.Text));
await hub.Send("alice", "hello").FirstAsync();
int n = await hub.GetUserCount().FirstAsync();
hub.Counter(10, 500).Subscribe(i => Console.WriteLine(i));
```

设计要点：

- **入口对齐 RestAPI**：`HubService.For<T>(HubConnection)`，配 `RegisterGeneratedFactory(Type, Func<HubConnection, object>)`（模块初始化器注册，运行期无反射，AOT 友好；见 `RestService.For<T>` 范式）。
- **调用 / 发送 / 流**为**方法**（可带参数）；**回调**为**属性**（无参，订阅即注册）。形态不符报诊断（见 §4）。
- **回调流为多播热流**：内部包一份引用计数，首个订阅者触发 `connection.On`，最后一个订阅者释放时调用返回的 `IDisposable` 注销，避免重复注册。

### 2.2 回调扩展模型（可选次形态，对齐 Events）

对仅需「裸 `On` → 流」而不想声明接口的场景，提供扩展入口（与 Events 的 `source.Events()` 同构）：

```csharp
// connection.On<ChatMessage>("ReceiveMessage", …) 的反应式封装
Observable<ChatMessage> stream =
    connection.HubCallbacks().On<ChatMessage>("ReceiveMessage");
```

该形态优先级低于 §2.1；可在接口模型落地后作为 follow-up 评估，避免首版面铺得过大。

### 2.3 特性集（运行时 `Observables.SignalR`）

| 特性 | 目标 | 含义 |
|------|------|------|
| `[Hub]` | interface | 标记需生成代理的 Hub 接口 |
| `[HubInvoke(name?)]` | method | `InvokeAsync<T>`；返回 `Observable<T>`（`T` 为结果类型） |
| `[HubSend(name?)]` | method | `SendAsync`；返回 `Observable<Unit>` |
| `[HubStream(name?)]` | method | `StreamAsync<T>`；返回 `Observable<T>`（多元素） |
| `[HubOn(name?)]` | property | `On<T>`；返回 `Observable<T>`（热/多播） |

- `name` 省略时默认取成员名（方法名 / 属性名）。
- 方法参数原样作为调用实参；`CancellationToken` 末位参数（若有）透传给 `InvokeAsync/StreamAsync`。
- 客户端 → 服务端的**上行流**参数（`IAsyncEnumerable<T>` / `ChannelReader<T>`）首版**不支持**，留作 follow-up（报 OBS4006）。

## 3. 生成物形状

### 3.1 后初始化固定产物（PostInitialization）

与 Events 一致，在 `RegisterPostInitializationOutput` 阶段发出与具体接口无关的桥接基础设施（hint 名 `Observables.SignalR.R3.*.g.cs`）：

- `HubService`：`For<T>` + `RegisterGeneratedFactory`（运行时类型在 `Observables.SignalR`，此处仅生成绑定壳，按 RestAPI 范式）。
- 桥接 helper（运行时类型，见 §5）：`SignalRObservable.FromInvoke<T>`、`FromSend`、`FromStream<T>`、`FromOn<T>`。

### 3.2 每接口产物（基于语法候选）

对每个 `[Hub]` 接口生成 `partial`/内部实现类 `{Interface}GeneratedProxy`（hint 名 `{SafeHintName}.SignalR.g.cs`），形如：

```csharp
// <auto-generated/>  —— GeneratedSourceHeader 统一头
namespace Observables.SignalR.R3.Generated
{
    internal sealed class ChatHubGeneratedProxy : global::IChatHub
    {
        private readonly global::Microsoft.AspNetCore.SignalR.Client.HubConnection _connection;

        public ChatHubGeneratedProxy(
            global::Microsoft.AspNetCore.SignalR.Client.HubConnection connection)
            => _connection = connection;

        public global::R3.Observable<int> GetUserCount()
            => global::Observables.SignalR.SignalRObservable
                .FromInvoke<int>(_connection, "GetUserCount");

        public global::R3.Observable<global::R3.Unit> Send(string user, string message)
            => global::Observables.SignalR.SignalRObservable
                .FromSend(_connection, "Send", user, message);

        public global::R3.Observable<int> Counter(int count, int delayMs)
            => global::Observables.SignalR.SignalRObservable
                .FromStream<int>(_connection, "Counter", count, delayMs);

        public global::R3.Observable<global::ChatMessage> ReceiveMessage
            => global::Observables.SignalR.SignalRObservable
                .FromOn<global::ChatMessage>(_connection, "ReceiveMessage");

        [global::System.Runtime.CompilerServices.ModuleInitializer]
        internal static void Register()
            => global::Observables.SignalR.HubService.RegisterGeneratedFactory(
                typeof(global::IChatHub),
                static c => new ChatHubGeneratedProxy(c));
    }
}
```

### 3.3 Reactive 后端差异

`Observables.SignalR.Reactive.SourceGenerators` 产出同构代码，仅替换返回类型与桥接命名空间：

- `R3.Observable<T>` → `System.IObservable<T>`，`R3.Unit` → `System.Reactive.Unit`
- `SignalRObservable.*` → `Observables.SignalR.Reactive.SystemReactiveSignalRAdapter.*`（`FromAsync` / `Create` 封装，见 RestAPI 的 `SystemReactiveObservableAdapter`）

R3 包不引用 System.Reactive，反之亦然（约定）。

## 4. 诊断表（`OBS4xxx`）

延续按域分段（Events `OBS2xxx`、RestAPI `OBS3xxx`）。Category 统一 `Observables.SignalR`，放入 `Observables.SignalR.SourceGenerators.Shared`：

| ID | 标题 | 严重度 | 触发时机 |
|----|------|--------|----------|
| **OBS4001** | Hub interface members must declare a SignalR boundary attribute | Warning | `[Hub]` 接口成员缺 `[HubInvoke/Send/Stream/On]`，或 name 实参非字面量 |
| **OBS4002** | Observables.SignalR must be referenced | Error | 发现 `[Hub]` 候选但未引用运行时/Client 程序集 |
| **OBS4003** | Unsupported member return type | Error | 返回类型不是 `Observable<T>` / `IObservable<T>`（Send 须 `…<Unit>`） |
| **OBS4004** | Member shape mismatch for SignalR boundary | Error | `[HubOn]` 用在方法、或 `[HubInvoke/Stream]` 用在属性等形态错配 |
| **OBS4005** | SystemReactive package required for IObservable | Error | Reactive 生成器遇 `IObservable<T>` 但未引用 `Observables.SignalR.Reactive`（镜像 OBS3005） |
| **OBS4006** | Unsupported streaming parameter | Error | 出现上行流参数（`IAsyncEnumerable<T>` / `ChannelReader<T>`）等首版不支持的形态 |

> 启用 analyzer release tracking 时，需在 `AnalyzerReleases.Unshipped.md` 登记上述 ID。

## 5. 运行时 vs 仅分析器

**需要共享运行时程序集**（与 RestAPI 同，区别于纯生成的 Events）：

| 项目 | 内容 | 进哪个包 |
|------|------|----------|
| `Observables.SignalR` | 特性（`[Hub]` 等）、`HubService`（`For` / `RegisterGeneratedFactory`）、`SignalRObservable`（R3 桥接 helper）、对 `Microsoft.AspNetCore.SignalR.Client` 的引用 | `Observables.SignalR.R3`（`lib/`） |
| `Observables.SignalR.Reactive` | `SystemReactiveSignalRAdapter`（`IObservable` 桥接） | `Observables.SignalR.Reactive`（`lib/`） |

- `FromInvoke/FromSend` ≈ `Observable.FromAsync`（冷、单元素）；`FromStream` 桥接 `IAsyncEnumerable<T>`（R3 `Observable.Create` + `await foreach`）；`FromOn` 为引用计数多播（首订阅 `connection.On`，末订阅 `Dispose`）。
- `Microsoft.AspNetCore.SignalR.Client` 作为运行时包的 **public 依赖**（消费者通过 `HubConnection` 传参，必须可见）。

## 8. 非目标

- 设计期**不**改版本号、不打 tag、不发 NuGet。
- **不**与 Events / RestAPI 混 PR；每模块独立 Issue → 分支 → PR。
- 首版不支持上行（客户端→服务端）流参数、不支持服务端侧 Hub（仅客户端代理）。
